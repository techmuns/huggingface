Methodology & caveats
  • Source: Hugging Face Hub API, walked newest-first each week. Raw payloads are stored immutably, so the taxonomy can be re-run over history without re-scraping.
  • Spaces are de-duplicated by normalised title plus linked-model set; template clones collapse to one representative, because a single viral template can otherwise manufacture a trend.
  • Classification runs deterministic rules first (tags, linked models, slug, README prose) at zero cost; only what the rules cannot settle is sent to a model. Every row records which produced it, and a confidence score.
  • Primary use case is single-valued, so its shares total 100%. Vertical, technology and model family are multi-label — those are penetration rates and deliberately do not total 100%.
  • Time periods. Everything on the page is built from one figure per week. A month is every week whose Monday falls inside it, and a quarter is three of those months, so no week is ever counted twice or split across two columns. Counts are added up within a period; percentages are pooled — each week weighted by how many Spaces it had — because percentages cannot be added. Engagement is neither: downloads are a rolling 30-day figure and likes are a running total, so a period reports its last measured week rather than a sum.
  • Growth compares each period against the period immediately before it — week on week, month on month, quarter on quarter. A count is only compared when both periods hold the same number of measured weeks: a month three weeks in against a full one would read as a fall that is really just days that have not happened yet. Those cells show “part period” instead of a number. Shares are comparable either way, because a share does not grow with the length of the period.
  • A figure on a base below the reporting threshold is shown greyed and marked “too few” rather than printed as a confident percentage. A period is only marked that way when every week in it was.
  • Roughly half of new Spaces arrive with no description and no linked model. Those get a README fetch; what remains unclassifiable is counted in coverage rather than quietly dropped.
  • A category with no row in a period the pipeline did measure scored zero and is drawn as zero; a period nothing was measured in is a gap, not a zero. Stacked bars are only used where every item is counted once and the parts really do make a whole — use case, model family and SDK. Multi-label cuts, where one Space can appear in several categories, are drawn side by side instead, because stacking them would invent a total that does not exist.

What each chart counts

  • What developers are building. Primary use case — one per Space, so shares total 100%.
  • Where they're building it. Vertical — multi-label, so these do not total 100%.
  • What they're building on. Model family, from declared base_model lineage.
  • How they're building it. Technique — multi-label, on its own tab. The build SDK is separate, under How they build.
  • Model family by use case. Share of each use case's Spaces built on a given family.
  • Engagement. Downloads are a rolling 30-day rate; likes are cumulative.
  • The matrix asterisk. Base below the reporting threshold — shown for completeness, not as a trend.
